## 2026-11-17

### 1. 规则引擎：自定义盒按用户规则参与自动归类

**创意描述**：目前自定义盒（Category.custom）纯手动策展、不参与自动归类。允许用户为任意盒挂载规则（按后缀 / 文件名关键字 / 通配符，如 `*.psd → 设计盒`、`*发票* → 报销盒`），一键整理时命中规则的文件优先流入对应自定义盒，规则未命中的再走默认后缀分类。

**价值**：高。物理移动派竞品（元气/DeskGo）的规则整理只允许改默认分类映射，不支持"一个规则槽位绑到一个用户自建分组"；这是自定义盒体系天然长出的能力，竞品学不来。对有明确工作流（设计稿、发票、安装包归档）的用户是从"能用"到"离不开"的关键。

**可行性**：高。`move_path`/scan 管线与 `Category.custom` 标志均已存在，只需在 Config 增加 `customBoxes[].rules: {pattern, strategy}[]` 并在自动归类决策链最前面插入规则匹配（glob 匹配引入现成 crate，无需自写）。

**优先级**：⭐⭐⭐ 高

### 2. 卸载前自动还原（NSIS 卸载钩子）

**创意描述**：卸载程序时先调用应用自身的"全部还原"逻辑，把 `桌面\桌面整理\` 下的文件搬回桌面原位（搬不动/有冲突的逐项列清单），再询问"是否继续卸载"。NSIS 卸载流程里加一个 custom page / 预卸载步骤。

**价值**：高。卸载是用户流失的最后一刻，也是信任崩塌点——竞品普遍直接卸载，留下"我的文件被塞进一个文件夹、应用没了"的烂摊子（DeskGo 曾因此被大量吐槽）。"卸载也把桌面还给你"本身就能写进 README 当卖点，与 OneDrive 检测、"一切可还原"的产品人设一脉相承。

**可行性**：中。release.yml 已是 NSIS 打包，钩子技术上可行；难点在于卸载器需要独立还原逻辑或静默调用残留的 exe（可在卸载早期于 %TEMP% 解一个 mini helper，或直接以命令行参数 `puredesk.exe --uninstall-restore` 复用主程序 restore_all）。边缘场景（桌面路径被重定向、文件被占用）需要逐项报告兜底。

**优先级**：⭐⭐ 中

### 3. 整理洞察面板（基于 moves.jsonl 的使用统计）

**创意描述**：主面板加一个"整理回顾"小页：本周/近 30 天搬移了多少文件、哪些类别最多（应用/文档/图片…）、最高频的来源路径、撤销次数。数据全部来自已有的 `moves.jsonl` 移动日志，零新增采集。

**价值**：中高。四家竞品均无使用洞察，属于纯差异化；对用户是"这个软件真的在帮我"的可感反馈（"本周自动整理了 137 个文件，省去 137 次手动拖拽"），也天然适合日后做周报 toast 或截图分享，是低成本的增长素材。

**可行性**：高。moves.jsonl 已记录 from → to 与成败，前端读日志聚合即可；注意按批次去重、剔除自愈骨架清理的噪音条目、控制读取量（只聚合最近 N 千行）。

**优先级**：⭐⭐ 中

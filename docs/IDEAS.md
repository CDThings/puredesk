## 2026-11-17

### 1. 规则引擎：自定义盒按用户规则参与自动归类

**创意描述**：目前自定义盒（Category.custom）纯手动策展、不参与自动归类。允许用户为任意盒挂载规则（按后缀 / 文件名关键字 / 通配符，如 `*.psd → 设计盒`、`*发票* → 报销盒`），一键整理时命中规则的文件优先流入对应自定义盒，规则未命中的再走默认后缀分类。

**价值**：高。物理移动派竞品（元气/DeskGo）的规则整理只允许改默认分类映射，不支持"一个规则槽位绑到一个用户自建分组"；这是自定义盒体系天然长出的能力，竞品学不来。对有明确工作流（设计稿、发票、安装包归档）的用户是从"能用"到"离不开"的关键。

**可行性**：高。`move_path`/scan 管线与 `Category.custom` 标志均已存在，只需在 Config 增加 `customBoxes[].rules: {pattern, strategy}[]` 并在自动归类决策链最前面插入规则匹配（glob 匹配引入现成 crate，无需自写）。

**优先级**：⭐⭐⭐ 高

### 2. 卸载前自动还原（NSIS 卸载钩子）

**创意描述**：卸载程序时先调用应用自身的"全部还原"逻辑，把 `桌面\桌面整理\` 下的文件搬回桌面原位（搬不动/有冲突的逐项列清单），再询问"是否继续卸载"。NSIS 卸载流程里加一个 custom page / 预卸载步骤。

**价值**：高。卸载是用户流失的最后一刻，也是信任崩塌点——竞品普遍直接卸载，留下"我的文件被塞进一个文件夹、应用没了"的烂摊子（DeskGo 曾因此被大量吐槽）。"卸载也把桌面还给你"本身就能写进 README 当卖点，与 OneDrive 检测、"一切可还原"的产品人设一脉相承。

**可行性**：中。release.yml 已是 NSIS 打包，钩子技术上可行；难点在于卸载器需要独立还原逻辑或静默调用残留的 exe（可在卸载早期于 %TEMP% 解一个 mini helper，或直接以命令行参数 `puredesk.exe --uninstall-restore` 复用主程序 restore_all）。边缘场景（桌面路径被重定向、文件被占用）需要逐项报告兜底。

**优先级**：⭐⭐ 中

---

### 3. 整理洞察面板（基于 moves.jsonl 的使用统计）

**创意描述**：主面板加一个"整理回顾"小页：本周/近 30 天搬移了多少文件、哪些类别最多（应用/文档/图片…）、最高频的来源路径、撤销次数。数据全部来自已有的 `moves.jsonl` 移动日志，零新增采集。

**价值**：中高。四家竞品均无使用洞察，属于纯差异化；对用户是"这个软件真的在帮我"的可感反馈（"本周自动整理了 137 个文件，省去 137 次手动拖拽"），也天然适合日后做周报 toast 或截图分享，是低成本的增长素材。

**可行性**：高。moves.jsonl 已记录 from → to 与成败，前端读日志聚合即可；注意按批次去重、剔除自愈骨架清理的噪音条目、控制读取量（只聚合最近 N 千行）。

**优先级**：⭐⭐ 中

## 2026-11-18（灵感来源：开源灵动岛项目「岛仔」xiaotang-daozai + fly-island）

> 收纳岛本体（顶部灵动岛式状态胶囊：收起态常驻顶部显示收纳/待整理计数，悬停展开分类明细与快捷操作，organize-report 到达时播放活动动画）已直接落地并进 Roadmap。以下为沿"灵动岛"方向继续发散的后续创意。

### 4. 岛上驻留（dwell）提醒：桌面文件躺了几天了

**创意描述**：待整理文件在桌面停留超过 N 天（默认 3 天，可配）时，岛轻膨胀并在待整理区给该项标"已躺 3 天"；超过 7 天的条目排到待整理列表最前并橙色高亮。灵感：DeskBox 的 dwell 稳定态保护 + 岛仔的"信息轻轻出现"。

**价值**：高。桌面凌乱的本质是"文件的惰性"——竞品都在管"搬"，没人管"催"。温和的驻留提示是用户真正开始依赖自动整理的心理推手，也是截图传播的天然素材（"我的桌面没有躺超过 3 天的文件"）。

**可行性**：高。`DesktopItem.mtime_ms` 已随扫描返回，纯前端计算即可（无需新后端）；阈值可先做死配置再进设置页。

**优先级**：⭐⭐⭐ 高

---

### 5. 拖文件到岛 → 分类环（快速手动归类）

**创意描述**：把桌面文件拖到收纳岛胶囊上 → 岛立即展开为分类选择器（各启用盒成一列高亮块，数量多的盒更大），悬停某个盒高亮，松手即 `organize_paths` 归位；按住 Ctrl 松手 = 移动副本（copy-first 借鉴 DeskBox）。

**价值**：高。填补"不想一键整理、也不想开主面板"的中间态：单文件手动归类从右键三步变为一拖一放；岛的顶部居中位置天然是拖拽落点。

**可行性**：中。盒子窗口已有完整 `onDragDropEvent` 处理可移植（box.ts:204-227），岛需补 drag-over 时触发展开、drop 时目标盒高亮；后端 `organize_paths` 命令现成。

**优先级**：⭐⭐ 中

---

### 6. 桌面健康分（岛上的 gamification）

**创意描述**：胶囊左侧显示一个 0-100 的"桌面健康分"（待整理数量、最老驻留天数、近 7 天整理频率加权计算），展开面板显示分数构成与环比；分数达 95+ 时胶囊短暂播放彩虹动画。

**价值**：中高。把"整理桌面"从家务变成可累积的正反馈，四家竞品均无此概念；健康分也是周报/分享功能的天然载体，为后续增长功能铺数据地基。

**可行性**：高。三项输入数据全部已有（scan.items、mtime_ms、moves.jsonl）；纯前端计算，注意权重可调且默认口径保守（待整理 <5 项即 90+，避免永远不及格打击用户）。

**优先级**：⭐⭐ 中

### 7. 岛的全屏感知：检测到全屏应用时自动隐藏

**创意描述**：前台窗口进入全屏（游戏/视频播放器/演示）时，岛自动滑出屏幕隐藏；退出全屏后滑回。可用 Win32 判断前台窗口矩形是否覆盖整屏 + `WS_CAPTION` 缺失来识别全屏态，轮询 1~2s 足够。

**价值**：中高。收纳岛常驻置顶的天然代价是覆盖全屏内容（2026-11-18 实测冒烟时正好撞上全屏视频）——灵动岛在 iOS 之所以不烦人，是因为它内建于硬件；Windows 上的岛必须自己学会"让位"。这是岛能否长期常驻的体验分水岭。

**可行性**：中。winutil 已有窗口枚举/置底等 Win32 积累，新增 `is_foreground_fullscreen()` 即可；岛窗口配合 set_position 滑出/滑回（或 hide/show）。注意任务栏全屏（自动隐藏任务栏的误判）白名单处理。

**优先级**：⭐⭐ 中

## 2026-11-19

### 8. 下载目录智能整理（桌面之外的收纳延伸）

**创意描述**：把自动整理的监听范围从桌面扩展到「下载」文件夹（可开关、可自定义目录）：下载完成的文件（排除 *.crdownload/*.part 等半成品）按后缀规则自动/提示式归位，如安装包 → `收纳区\下载\安装包`、压缩包 → `收纳区\下载\压缩包`，或直接并入现有分类。

**价值**：高。下载目录是比桌面更失控的重灾区（测试环境事实：用户桌面 35 项待整理，下载目录通常数倍于此），元气/DeskGo 均把"下载整理"作为标配功能验证过刚需；PureDesk 的 watcher+move 管线天然可复用，等于零架构成本多吃一个高频场景。

**可行性**：高。`notify` watcher 已跑通桌面监听（watcher.rs），加一个目录实例即可；`move_path`/scan 排除规则现成；注意与浏览器"下载中"半成品扩展名的竞态（沿用现有 DEFAULT_EXCLUDES 的思路，mtime 稳定 3 秒才搬）。

**优先级**：⭐⭐⭐ 高

---

### 9. 重复文件感知：桌面与收纳区去重提示

**创意描述**：扫描时对桌面文件与收纳区做轻量指纹比对（同名+同大小，可选快速 hash），发现"桌面上的文件收纳区已有"时在待整理列表标"疑似重复"，一键选择：跳过收纳 / 收纳并把桌面副本送回收站。不做自动删除，只做提示。

**价值**：中。桌面最常见的混乱来源之一是同一文件反复下载/复制（report(3).pdf）；DeskGo 的清理线证明去重是用户真实诉求。与"删除只走回收站"红线一致，纯提示不越权。

**可行性**：中。同名+同大小比对零成本（scan 已返回 size）；真 hash 仅在用户点击"确认重复"时对候选对计算（大文件分块读），避免扫描期 CPU 尖峰。注意误报保护：只提示、永不静默删。

**优先级**：⭐⭐ 中
